# bd8 — i16-lane inverse-transform ROW pass, measured (2026-07-23)

The Phase-C follow-up lever named in `bd8_i16_transform_2026-07-22.md` ("row-pass
i16 narrowing"): the inverse-transform ROW pass now runs the five audited DCT
kernels (idct4/8/16/32/64) on `i16x16` lanes — 16 rows per AVX2 vector — for
every transform 16+ rows tall at bd8, on BOTH the u8 (lowbd) and u16 (highbd)
entry points. Landed with this doc. Nothing here is projected; every number is a
same-environment paired callgrind measurement (see the `.meta`).

## What is narrowed (coverage as fractions; MISSING first)

**NOT narrowed (stays on the byte-identical i32x8 row pass):**

- **7 of 12 row 1-D kernels** — iadst4/8/16 + iidentity4/8/16/32 — for the
  same mechanical reasons as the column pass (`xtask/audit_i16_safety.py`,
  re-run this session: unclamped `wrapping_neg()` terminals over 17-bit
  transients in iadst8/16; unclamped sinpi-sum / NewSqrt2·x2·x4 multiply
  terminals in iadst4 / iidentity*).
- **DCT rows of transforms 4 or 8 rows tall** (TX_4X4/8X8/4X8/8X4/16X8/8X16→no
  — precisely: every tx_size with `row_n % 16 != 0`). One partial i16 batch
  executes the SAME kernel instruction count as one partial i32x8 batch PLUS
  the pack/widen overhead — a structural loss, so they stay i32 by design
  (not an audit failure).
- **bd10/bd12 rows** — the dispatch gate is `row_clamp == 16 && stage_range
  all 16`, which only bd8 satisfies (bd10/12 pass 18/20). Byte-identical i32
  path, unchanged.

**Narrowed: 5 of 12 row kernels** (idct4/8/16/32/64) for every bd8 transform
with `row_n % 16 == 0` (heights 16/32/64) — the DCT row work of all large
transforms, where the row-pass Ir lives. Fires on the shared
`try_inv_row_pass`, so the u16 highbd entry at bd8 gets the same win (the u16
microbench is therefore NOT an unchanged control this time, by design).

## Why it is byte-identical (row-specific argument)

At bd8 the row pass presents the SAME audited kernel contract as the Phase-C
column pass: the driver clamps every (possibly rect-scaled) input with
`clamp_value(_, bd + 8 == 16)` BEFORE the kernel (exactly the i16 domain),
`opt_range(8) == (16, 16)` so `stage_range == [16; 12]` for BOTH directions,
`cos_bit == 12`. The SAME generated i16 kernels run with lanes = rows. The
row-specific stages stay outside the kernel, each exact in its own domain:

- rect `round_shift(x * NewInvSqrt2, 12)` runs on the RAW i32 input in i32
  lanes (`mul_rshiftv`, exact for any i32) BEFORE the clamp — scalar order;
- the driver clamp is the saturating pack (== `clamp_value(_, 16)`);
- `round_shift_array(-shift[0])` (bit 1 or 2 for every eligible size; 0 is
  the scalar early-return identity, never instantiated as a shift — the
  const-0-shift guard) operates on kernel TERMINAL outputs (clamp_value
  outputs, i16) via the proven `mulhrs(v, 2^(15-bit))` identity;
- the store sign-extends i16 → i32 into the UNCHANGED row-major i32 `buf`, so
  every column pass (the landed i16 DCT pass and the i32 iadst/identity pass)
  reads byte-identical values to the i32 row pass — no interface change.

Gates (all green before push): the new `inv_row_pass_i16_bit_identical_to_
scalar_at_every_tier` differential (FULL i32 input domain — stronger than the
driver bound — × 5 kernels × heights 16/32/64 × rect on/off × shift 0/1/2 ×
every token permutation, distinct-sentinel buffers so a missed store cannot
false-pass), the existing per-kernel i16 differential (unchanged kernels),
`inv_txfm2d_lowbd_diff` + full aom-dsp 354/354, decode conformance 62/62 —
each in BOTH default and `AOM_FORCE_SCALAR=1` dispatch (bd8/bd10/bd12
vectors byte-identical + golden MD5).
